## 详细描述

```
把所有窗口、所有标签组的标签页，汇总到一张清单里。

浏览器自带的标签栏是横向的、单窗口的、按打开顺序排的。标签一多，标题就被挤成几个字，只能靠肉眼一个个点。

Tablu 把全部标签摊开成一张纵向清单，并且保留你自己建的标签组——组的颜色、名字、折叠状态都跟着 Chrome 走，不做任何重新组织。

■ 主要功能

· 一键唤起：工具栏图标或快捷键，面板从屏幕正中弹出
· 按标签组分层：组内标签装进独立容器，组头显示颜色和数量，可折叠
· 快速定位：顶部列出所有标签组，点一下滚到对应位置
· 键盘操作：↑ ↓ 移动、Enter 跳转，全程不碰鼠标
· 收藏标签：行首星标，一键收藏到书签
· 深色模式：跟随系统 / 浅色 / 深色
· 独立面板页：在 chrome:// 这类禁止注入的页面上，自动改为在标签页中打开

■ 为什么它不拖慢浏览器

只有你点击图标时，脚本才会注入当前这一个页面。没点过的标签页零开销——开 50 个标签也不会多出 50 份运行时。

■ 隐私

· 不联网：代码里没有任何网络请求，标签页和书签信息不离开这台设备
· 不上传：没有服务器，没有账号，没有统计
· 不常驻：不申请 host_permissions，Chrome 的权限提示是"仅在您点击扩展程序时访问当前页面"

全部逻辑在本地运行，源码公开：https://github.com/runtuBro/chrome-tablu
```

## 隐私实践（Privacy 标签页）

**单一用途说明**

```
把所有窗口和标签组中的标签页汇总到一个面板里，供用户查看、搜索定位和切换。
```

英文（如果后台允许填英文，或未来做英文版）：

```
To present all tabs across every window and tab group in a single panel, so the user can review and switch between them.
```

**远程代码**：否（`No, I am not using remote code`）

**数据使用**：不收集任何用户数据。勾选"不收集"后，仍需勾选有限使用承诺（Limited Use）的几条声明。

## 权限理由

8 个权限逐个说明，可直接粘贴到后台的 Permissions justification 字段。

| 权限 | 理由 |
|---|---|
| `tabs` | 读取所有窗口的标签页标题与网址，用于在面板中列出；点击条目时激活对应标签；点击 × 时关闭该标签。 |
| `windows` | 点击属于其他窗口的标签时，需要先聚焦那个窗口再激活标签，否则在部分平台上不生效。 |
| `favicon` | 通过 `chrome://favicon` 接口获取站点图标。直接使用页面的 favIconUrl 会受宿主页面 CSP 的 img-src 限制而加载失败。 |
| `scripting` | 用户点击图标时，向当前页面注入面板脚本。本扩展没有常驻 content script，注入是唯一入口。 |
| `activeTab` | 仅在用户点击图标时获得当前页面的临时访问权限，用于上述注入。正因为有这个权限，本扩展不需要申请 host_permissions。 |
| `tabGroups` | 读取标签组的名称、颜色和折叠状态，用于在面板中按组分层展示。**只读，不会修改用户的分组**。 |
| `storage` | 保存用户的四项设置（主题、语言、面板高度、排序方式）。不存储任何标签页或书签数据。 |
| `bookmarks` | 判断某个标签的网址是否已被收藏，以决定星标显示实心还是空心；用户点击星标时创建或删除对应的书签。 |

**审核时值得强调的两点**（写进单一用途或描述里都能降低被拒概率）：

1. **没有 `host_permissions`，没有常驻 `content_scripts`** —— 权限最小化的直接证据。
2. **`tabGroups` 是只读的** —— 很多标签管理类扩展被质疑越权，明确说明只读能减少来回。
